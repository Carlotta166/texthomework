### 003 · 课堂提问

针对"词频统计能反映什么、存在什么问题、为什么不足以确定关系"三问作了完整回答，核心观点：

- 词频反映**话语强度**而非语义方向，仅能作为关注度的代理变量；
- 本例未去停用词，虚词标点污染排名，另有词性未过滤、同义词未归并、否定未处理等六类问题；
- 词频是边际分布，**丢失词序与句法结构，无法判定"数字化"与"安全"是正向促进还是负向风险**；改进路径从共词分析 → 依存句法 → NER + 关系抽取 → 大模型抽取，逐级递进。

### 004 · 课堂提问

- 评价了 DeepSeek 用于实体抽取的体验：门槛低、成本低、迭代快，但存在幻觉、格式不稳、不可复现等局限；
- 判断大模型优势在于**能理解专业语境**（通用 NER 识别不出 `scRNA-seq`、`pseudotime` 这类术语），劣势在规模化成本与稳定性；
- 关系识别部分：设计了限定关系闭集、要求依据原文、强制 JSON 输出的提示词，让模型在实体基础上输出 `(头实体, 关系, 尾实体)` 三元组，并给出理想结果示例与技术路线还原。

## 四、主要结论

1. **分词层面**：jieba 在通用词汇上表现稳定，失分点集中在专有名词。实测发现三类典型错误——"12日出"（应为"12日/出生"，未登录词歧义）、"中/船/重工/集团公司"（专有名词被切碎，加词典后修复）、"副/总工程师"（词典未收录，加词典也无改善）。这说明**词典可以治标，专业 NER 模型才能治本**。
2. **词频层面**：词频只能回答"提到了多少次"，不能回答"怎么提的"。要识别实体间关系，必须引入句法分析或关系抽取。
3. **大模型层面**：LLM 把实体与关系抽取的开发门槛降到了几十行代码，但对结果的校验和格式约束不可省。
